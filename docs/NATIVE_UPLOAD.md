# 桌面原生上传

在现有 Kotlin/JVM、Compose Desktop 和各网盘 API 上增加上传，复用现有登录账号及个人盘目录。文件由桌面客户端通过网盘 API 和授权存储传输，不依赖网页上传、Android 模拟器或额外中转服务，未引入新的运行时依赖。

## 接入范围

上传入口已接入夸克、UC、迅雷、百度、移动云盘（139）、123、115、光鸭、蓝奏云及蓝奏云优享版十个个人盘页面。各平台的文件类型、大小、空文件、配额和风控限制仍然生效。接入源码不代表所有平台的线上接口均已通过真实账号验证。

## 使用方法

1. 登录网盘，进入个人盘目标目录。
2. 点击工具栏上传图标，选择文件或文件夹；也可以直接拖入本地文件和文件夹。悬停图标可查看操作提示。
3. 统一选择窗口支持 Ctrl/Shift 多选文件和文件夹。双击文件夹进入目录，选中文件夹后点击“选择”添加整个文件夹。核对确认窗口中的目标目录、相对路径和大小，再开始上传。首次选择时取消，不会继续弹出空确认窗口。
4. 在“设置 → 上传 → 上传并发数”设置每个网盘的文件级并发上限，范围 1–10，默认 3。设置会保存；调高时补充任务，调低时不取消已开始的任务。
5. 上传过程中仍可点击上传图标或拖拽追加。追加沿用原账号和目标目录。已有待选项目时取消追加，会保留原列表。
6. 点击上传详情外的遮罩可收起窗口，右下角卡片继续显示进度、总速度和预计剩余时间；重新打开详情可查看每项状态。
7. 失败项可单独重试，也可点击“重试失败的 N 项”。仅重新排队失败项，已完成和取消项目不重传。

上传入口采用支持文件与文件夹混选的 Swing `JFileChooser`，设置系统外观。其他导入、保存和目录设置入口继续沿用原选择器。

## 文件夹与队列

- 在后台递归扫描元数据，保留所选根文件夹、子目录和空目录，不把文件内容整体读入内存。扫描可取消；不跟随符号链接、目录联接或特殊文件，不直接上传磁盘根目录。
- 本地路径去重，相同目录根只扫描一次；移除所选文件夹时一并移除其子项目。
- 每批次维护独立的远端目录映射。建目录前翻页查找并复用同名目录；同名文件阻挡目录、多个同名目录或分页异常时使相关项失败，避免猜测路径或重复建目录。
- 仅目录解析和创建互斥，文件传输仍可并发。同一目标相对路径的同名文件按序执行，不同子目录的同名文件可以并行。
- 准备、哈希、传输和网盘确认均占用并发名额。实际正在发送数据的文件数可能小于配置值；单个文件内部仍按平台协议顺序传输分片。
- 普通文件失败后继续处理其他项目。明确的账号缺失、已知失效或账号切换会停止新任务；上传期间限制该平台账号切换、添加和退出。
- 取消会中止队列及跟踪中的 HTTP 请求，退出程序也会请求取消。已经创建的目录和已经保存的文件不会回滚。

## 进度、速度与预计时间

- 每项显示准备、上传、确认、排队、成功、失败或取消状态；后台和详情均可滚动查看任务。
- 整批速度按最近五秒实际发送的字节增量统计，每 500 毫秒采样。哈希读取、建目录、秒传及确认阶段的进度跳变不计作网络速度。
- 预计剩余时间按尚待发送的整批字节数除以总速度计算，秒数四舍五入。失败、取消项的未传字节不计入剩余工作。
- 无有效采样时显示速度或时间占位状态；总大小尚未解析时标明“总大小未知”，不显示虚假的 0% 完成率。估算不包含本地准备或服务端确认耗时。
- 时间区域固定为 132 × 28 dp，并使用等宽字体；后台统计放在限高任务列表上方，避免多任务挤掉速度和时间。
- 普通字节进度按整批限频为最多每 200 毫秒一次；阶段变更、完成、取消、追加和并发设置变更立即发布。此限频不限制实际上传速度。

## 实现位置

| 位置 | 职责 |
| --- | --- |
| `data/upload/UploadSource.kt`、`UploadSelection.kt` | 本地文件流、元数据、目录扫描与去重 |
| `data/upload/UploadIo.kt`、`UploadSigning.kt` | 可取消的流式 I/O、摘要、签名及对象存储传输 |
| `data/upload/UploadRequestInterceptor.kt` | 跟踪控制请求和响应体生命周期，避免上传写操作被自动重放 |
| `data/upload/UploadRunner.kt`、`UploadFileProgress.kt` | 并发调度、追加、重试及字节采样 |
| `data/upload/UploadDirectoryResolver.kt` | 远端目录映射、建目录互斥及分页边界处理 |
| `data/upload/UploadSessions.kt` | 上传会话及账号操作互斥 |
| `data/network/*Api.kt`、`QuarkUpload.kt` | 各网盘上传协议，复用既有账号和请求客户端 |
| `ui/components/UploadPane.kt` | 上传选择、确认和拖拽入口 |
| `ui/components/UploadProgressDialog.kt`、`UploadProgressHost.kt` | 详情窗口及主窗口常驻后台卡片 |
| `ui/viewmodel/*CloudViewModel.kt`、`ui/screens/*CloudScreen.kt` | 个人盘目录与上传任务的增量接入 |

诊断网络拦截器跳过带上传上下文的请求，避免提前读取或重复读取文件体，也避免将上传控制响应中的临时密钥写入诊断日志。测试偏好设置使用独立内存存储，数据库目录指向构建目录，避免测试源码在执行时改写用户配置。

## 已知限制

- 重试是用户显式发起的重新上传，不是分片断点续传；不包含自动无限重试、暂停恢复、重启恢复或持久化上传历史。
- 若服务器已经保存文件、只有确认响应丢失，重新上传可能产生重复文件。重试前建议刷新远端目录核实。
- 未实现统一的远端 multipart abort，取消后不保证清除平台暂存分片；同名文件的处理沿用各平台协议。
- 文件变化检查基于元数据，不是写入锁。上传期间应避免修改本地源文件。
- 本次不更换上游更新源、应用名称、安装 AppId、数据目录或通知身份，也不改造下载架构。
